# 判断テンプレート

## 相談が必要な場面

- スコープ、受け入れ条件、優先度が変わる。
- 実装方針に意味のあるトレードオフがある。
- セキュリティ、UX、保守性のリスクを受容する必要がある。
- 既存ドキュメントと意図する挙動が食い違う。
- Manager が選ぶとプロダクト判断を代行してしまう。

## 選択肢の作り方

よい選択肢は次を満たす。

- 互いに違いが明確。
- 後で実装可能な粒度。
- コスト、リスク、ユーザー影響で比較できる。
- ユーザーが実際に決める必要がある範囲に絞られている。

## エスカレーション形式

```md
判断が必要です。

推奨は A です。理由は ...

- A: ...
- B: ...
- C: ...

決めてほしいこと:
- ...
```

## 決定事項の記録

- 決まった内容
- 判断者
- 必要なら日付
- 次に進められる工程
- 受容したリスク
