# 調査チェックリスト

## 範囲

- 答えるべき問いは何か。
- 対象のファイル、モジュール、文書、ログはどれか。
- 明示的に対象外の範囲はどこか。
- 情報は安定しているか。最新情報の確認が必要か。

## 根拠

- ファイルパスと該当箇所
- 実行したコマンドと重要な結果
- 既存テスト、またはテストが存在しない事実
- 回答を制約する仕様やロール定義

## 専門エージェント起動条件

- Security: 外部入力、認証、公開エンドポイント、秘密情報、ネットワーク通信、依存関係。
- UX Reviewer: ユーザーに見える UI、CLI 文言、通知、フォーム、操作フロー。
- Structure Reviewer: ディレクトリ構成、ファイル所有、命名、依存方向。
- Spec Reviewer: `work/` 配下の仕様と実装の不一致。
- Developer: 実現可能性、実装上の制約、テスト可能性。

## 出力品質

- 事実と推論が分かれている。
- 指摘が範囲内で具体的。
- 不明点に「なぜ重要か」が書かれている。
- 推奨する次工程が明確。
