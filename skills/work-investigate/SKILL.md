# Work Investigate

## 目的

相談、計画、実装の前に事実を集める。
出力は根拠、影響、選択肢、不明点であり、意思決定記録ではない。

## 入力

- ユーザー依頼または調査したい問い
- 対象ファイル、モジュール、ログ、文書
- 制約、期限、触ってはいけない範囲
- 専門レビューが必要な場合は `roles/` の該当ロール定義

## Manager の進め方

1. 調査する問いと範囲を明確にする。
2. まず最小限の関係ファイルや成果物を確認する。
3. どの専門ロールが有用か判断する。
4. 並列レビューでリスクが下がる場合だけ、範囲を絞って依頼する。
5. 事実、影響、選択肢、不明点に整理する。
6. 相談、計画、終了のどれに進むか決める。
   調査から実装へ直接進めない。実装が必要な場合は、実装開始条件が揃っていることを計画工程で確認する。

## 専門エージェントの使い方

専門エージェントは、調査品質やリスク判断が実際に改善する場合だけ使う。

- `Security`: 外部入力、認証、公開機能、秘密情報、外部通信、依存関係。
- `UX Reviewer`: GUI、CLI 文言、フォーム、通知、ユーザー向けフロー。
- `Structure Reviewer`: フォルダ構成、ファイル配置、責務境界。
- `Spec Reviewer`: `work/` 配下の仕様書と実装の整合性。
- `Developer`: 実現可能性やコード上の事実確認のみ。read-only / no edits / no implementation。

## 引き継ぎルール

サブタスクに必要な文脈だけを渡す。

- 目的
- 対象ファイルまたは成果物
- 制約
- 具体的な問い
- 期待する出力形式

専門エージェントが必要としない限り、会話全体は渡さない。

## やること

- 観測した事実と推論を分ける。
- 可能な限り具体的なファイル、節、コマンドを示す。
- 未解決の問いを明記する。
- 次工程に進めるだけの情報が揃ったら止める。

## やらないこと

- ファイルを変更しない。
- ユーザーの代わりに仕様や方針を決めない。
- 実装を始めない。
- 専門エージェントに調査全体を丸投げしない。
